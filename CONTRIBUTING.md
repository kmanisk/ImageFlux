# Contributing

Contributions are welcome. Keep changes small, focused, and easy to verify.

## Workflow

1. Branch from `master`.
2. Follow the setup instructions in `README.md` and verify the current project before making changes.
3. Keep each pull request limited to one feature, fix, or documentation improvement.
4. Run the relevant formatter, linter, build, and tests available in the repository.
5. Describe the change and the verification performed in the pull request.

For image-processing changes, include representative input/output examples when practical and avoid committing large generated assets unless they are required fixtures. Never commit credentials, local caches, or editor-specific files.
